1. この文書の目的
本ドキュメントは、
「komet で合格した状態を、そのまま一切改変せず komenoichi にデプロイする」
ための 実証済み・再現可能な手順 をまとめた基準文書である。

特に以下を保証する：

本番（komenoichi）を汚さない

中途半端な状態が本番に出ない

複数回 push したリハーサル履歴をすべて内包した 最終合格状態のみ を本番に反映する

将来、手順を忘れてもこの文書とコマンドだけでDB更新まで完全に復元できる

2. 前提条件
ローカル開発フォルダは 常に1つだけ

通常： Desktop/komet

本番用フォルダは デプロイ時にのみ一時的に作る

Desktop/komenoichi

本番デプロイ完了後、komenoichi フォルダは 必ず削除 する

3. 基本思想
3.1 Git は「フォルダ」ではなく「commit」を配る
push されるのは 最後の commit

その commit には、それ以前の変更がすべて含まれる
→ kometでの複数回の試行錯誤（pushA/B/C...）を経て、最終的に「OK」となった状態の commit を、そのまま本番（komenoichi）の履歴として「上書き同期」させる。

3.2 リポジトリの所在（宛先）
リハーサル用： https://github.com/naokit1928/komet-api.git

本番用： https://github.com/naokit1928/komenoichi.git

4. 本番デプロイ実行手順（完全ワークフロー）
Step 1：komet（リハーサル）を完璧にする
Desktop/komet で開発を行う。

git add . / git commit / git push を行い、GitHub(komet)へ送信。

リハーサル環境で動作を確認し、合格 したら次へ進む。

Step 2：本番用フォルダの作成（物理コピー）
デスクトップの komet フォルダを右クリックし 「コピー ＆ 貼り付け」 する。

複製されたフォルダの名前を komenoichi に変更する。

Step 3：Git宛先の書き換え（※最重要項目）
コピー直後の komenoichi フォルダは、内部のGit設定（.git）が komet を向いているため、これを本番用に修正する。

PowerShell
# PowerShell で実行
cd C:\Users\ntnao\Desktop\komenoichi

# 宛先を本番リポジトリに変更
git remote set-url origin https://github.com/naokit1928/komenoichi.git

# 宛先が正しく変わったか指差し確認
git remote -v
# ※ origin https://github.com/naokit1928/komenoichi.git (push) と出ればOK
Step 4：状態チェック（必須）
PowerShell
git status
# 「nothing to commit, working tree clean」であることを確認。
# ※ 変更が残っている場合は、komet側でのコミット漏れのため、やり直すこと。
# ※ Untracked files（Git管理外のファイル）が赤字で出る分には無視してよい。
Step 5：本番にプッシュ（強制同期）
履歴が異なるリポジトリ同士を同期させるため、強制プッシュ（-f）を使用する。

PowerShell
git push -f origin main
これにより、kometで合格した最終状態がそのまま本番（komenoichi）へ完全にコピーされる。

Step 6：Render と Vercel のデプロイ見守り
GitHubへのpushをトリガーに自動デプロイが走る。

【⚠️ Vercelがエラーで落ちた場合の対応】

原因： Vercel（フロント）のビルドが速すぎて、Render（バックエンド）の再起動完了前にAPI仕様書を取りに行き、タイムアウトしたため。

対策： Renderのステータスが「Live」になったのを確認してから、Vercelのダッシュボードで失敗したデプロイの右端の「︙」から 「Redeploy」 をクリックする。

Step 7：本番DBのアップデート（スキーマ変更時のみ）
テーブル追加やカラム変更があり、**「本番データを全消しして再構築してもよい場合」**は以下の手順を行う。
（※ コードがデプロイされただけではDB構造は更新されないため必須）

PowerShell
# ローカルまたはRenderのShellから実行
python app_v2/models/init_db.py
Step 8：完了後のクリーンアップ
誤操作（本番フォルダで開発を始めてしまう等）を防ぐため、用が済んだフォルダは削除する。

PowerShell
cd ..
Remove-Item -Recurse -Force .\komenoichi
